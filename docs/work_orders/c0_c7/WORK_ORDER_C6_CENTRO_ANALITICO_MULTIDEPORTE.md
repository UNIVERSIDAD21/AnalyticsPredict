# WORK_ORDER_C6_CENTRO_ANALITICO_MULTIDEPORTE.md

## Objetivo
Construir una experiencia multideporte unificada, honesta y escalable, sin fusionar a la fuerza semánticas distintas ni ocultar diferencias de madurez.

## Problemática
Existe deseo de unificación del producto, pero unir pantallas a ciegas puede mezclar dominios con distinta madurez y distinta función. C6 debe resolver la experiencia, no maquillar el estado real del sistema.

## Tareas obligatorias
1. Diseñar shell común y navegación común.
2. Definir KPIs base compartidos entre deportes.
3. Incorporar selector de deporte y visualización de madurez/estado.
4. Mantener paneles específicos donde el dominio lo requiera.
5. Definir contrato base de métricas comunes.
6. Actualizar documentación de producto, estado y changelog.

## Entregables
- Dashboard principal unificado.
- Navegación común.
- Selector/filtro por deporte.
- Contrato base de métricas comunes.

## Restricciones
- No crear una pantalla monolítica que mezcle lógicas incompatibles.
- No usar la unificación visual para ocultar deuda de fútbol.
- No romper foco del camino principal de caja y hardening.

## Criterio de cierre
Existe una experiencia multideporte coherente, honesta y escalable, con madurez visible por deporte.
