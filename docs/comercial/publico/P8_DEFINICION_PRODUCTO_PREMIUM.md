# P8 — Definir mejor el producto premium

Fecha: 2026-03-24
Estado: APROBADO PARA EJECUCIÓN
Prioridad: P1

## Problema
Si el sistema avanza hacia un esquema freemium, el premium no puede justificarse solo por “más cantidad”. Debe sentirse como una capa claramente superior de valor, continuidad y profundidad.

## Objetivo
Definir el producto premium como una experiencia más seria y útil, no simplemente como desbloqueo arbitrario de análisis.

## Alcance
### Sí incluye
- definición de beneficios premium reales,
- separación clara entre gratis y pago,
- profundidad funcional superior para suscritos,
- conexión entre premium y trazabilidad/seguimiento,
- lenguaje comercial honesto para la mensualidad.

### No incluye
- paywall agresivo sin propuesta clara,
- premium vacío basado solo en límites de uso,
- vender humo como “ventaja secreta”.

## Posibles ejes premium
1. Mayor profundidad analítica.
2. Historial y bitácora avanzada.
3. Métricas extendidas y comparativas.
4. Alertas y continuidad.
5. Seguimiento más fino por mercados/deportes/competencias.
6. Mejor lectura operativa del riesgo.

## Decisiones aprobadas
- premium debe ser profundidad y continuidad,
- el usuario debe entender por qué pagar tiene sentido,
- la mensualidad debe sentirse como acceso a una capa superior del producto, no solo como eliminación de bloqueo.

## Entregables esperados
- tabla comparativa visitante / registrado / premium,
- definición funcional del premium,
- copy comercial de conversión a premium,
- lista de features premium prioritarias,
- propuesta de paywall o CTA con lógica de valor.

## Criterio de done
- el premium tiene identidad clara,
- el usuario entiende qué compra y por qué,
- la separación gratis/pago deja de ser arbitraria,
- Borlty documenta el rationale de producto detrás del premium.

## Riesgos a controlar
- premium poco diferenciado,
- saturar gratis y dejar premium débil,
- vender premium demasiado pronto sin haber demostrado valor inicial.

## Métricas sugeridas
- conversión a premium,
- uso de funciones premium,
- retención de suscritos,
- cancelación temprana y motivos.

## Avance de ejecución (2026-03-26)
- Comparativa visible visitante/registrado/premium en landing pública.
- Premium definido como profundidad operativa superior, no solo desbloqueo de uso.

## Matriz funcional consolidada (actual)
- Visitante:
  - landing + centro analítico público,
  - sin bitácora ni personalización.
- Registrado:
  - análisis operativo completo,
  - bitácora y continuidad base,
  - configuración y onboarding.
- Premium:
  - seguimiento operativo ampliado,
  - lectura extendida de riesgo y señal,
  - prioridad en capas analíticas avanzadas.
